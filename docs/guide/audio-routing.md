# CoreAudio COM Routing & Endpoint Filtering

RigSwitch interfaces with Windows audio drivers using COM interop against the undocumented **`IPolicyConfig`** interface in CoreAudio (`MMDeviceAPI`).

---

## Default Audio Routing

When switching profiles, Windows needs to update two distinct default roles:
1. **`eConsole` (Multimedia)**: Used by games, music players, YouTube, and media streaming apps.
2. **`eCommunications` (Voice Chat)**: Used by Discord, Teams, and voice communication channels.

RigSwitch updates both roles atomically:
* If the primary device is connected and active, RigSwitch switches default playback to the primary endpoint.
* If the primary device is unplugged or powered down, RigSwitch switches seamlessly to the configured **Fallback Audio Endpoint** (e.g. monitor line-out or secondary speakers).

---

## Audio Endpoint Visibility Filtering

Modern gaming PCs frequently accumulate dozens of inactive or unwanted virtual audio endpoints generated by third-party software, including:
* SteelSeries Sonar virtual channels
* Oculus / Meta Quest audio drivers
* Steam Streaming Speakers
* Elgato Wave Link virtual mixes

In the **Audio Device Visibility** tab in Settings, RigSwitch lets you toggle individual endpoints. Hiding an endpoint instructs CoreAudio to hide the device from the Windows volume mixer dropdown, keeping your tray audio menu clean.

---

## Custom Nicknames

In the **Device Nicknames** tab, you can assign user-friendly aliases to obscure hardware device strings:
* E.g. Rename `Realtek High Definition Audio (Interface 2)` ➔ `Desk Pebble V3 USB`
* E.g. Rename `NVIDIA High Definition Audio` ➔ `Sim Rig 3.5mm Speakers`

These nicknames appear consistently throughout RigSwitch menus, preset selectors, and notifications.
